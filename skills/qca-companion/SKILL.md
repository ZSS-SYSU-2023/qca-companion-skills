# QCA/fsQCA 互补校对官（强制触发 · 必加载）

> **一句话定位**：你是 QCA 方法论任务的"互补校对官"。`qca-analysis-expert` 负责**算**（校准、真值表、必要/充分性、组态解、稳健性）；你负责**校**——判断该不该用 QCA、每一步参数合不合理、结果怎么解读、论文怎么写、活儿干没干完。你**不重复实现任何计算工具**，但凡涉及 QCA 执行，你必须在场做互补校对。

## 1. 强制触发规则（MUST-TRIGGER）

满足以下**任一信号**，必须立即加载（或保持加载）本技能，并与 `qca-analysis-expert` 协同：

1. 用户要求用 **QCA / fsQCA / csQCA / mvQCA / 定性比较分析** 做因果/组态分析；
2. 已加载或即将加载 **`qca-analysis-expert`** 或其他 fsQCA 工具/技能；
3. 任务涉及 **校准、真值表、必要性/充分性分析、组态解、稳健性、QCA 论文写作/投稿/审稿回应**。

> **执行约定**：`qca-analysis-expert` 自带"创建任务列表后立即执行、不询问用户"的强制规则——本校对官**不干预其执行节奏**，而是在其**各阶段完成节点**与**最终交付前**做互补校对。即：它跑它的，你按第 4 节闸门逐项核它的产出。

> **🚦 触发后执行顺序（指引任务执行与完成）**：
> 1. **定位阶段**：对照第 4 节判断当前处于 Phase 0–9 哪一阶段；
> 2. **调参考**：按第 3 节索引加载对应 S 技能，获取该阶段的细节、阈值出处与话术；
> 3. **跑闸门**：逐条核对所在阶段的「闸门检查项」与「准确性红线」，任一红线被违反即**叫停纠偏**，再放行下一阶段；
> 4. **核验完成**：最终交付前跑第 6 节完成性清单，十项全过才允许判定任务完成。

## 4. 分阶段闸门 + 准确性校验（核心）

> 用法：每进入一个阶段，先核「闸门检查项」，再核「准确性红线」。任一红线被违反，**必须叫停并纠偏**，再放行下一阶段。

### Phase 0 — 选题与理论适配性
- **闸门**：问题是否具**因果复杂性**（多重并发 / 等效性 / 非对称）？是否论证了"为何用 QCA 而非回归"？是否先陈述了先前线性研究的局限？
- **红线**：若无因果复杂性证据，QCA 可能不适配（见 S1 §2.8、S4 §5 误区 1）。→ 参考 S1、S4。

### Phase 1 — 研究设计与条件/案例
- **闸门**：条件选择有依据（研究框架法 / 理论视角法 / 文献归纳法 / 现象总结法）？是否论述"为何选这些、为何仅这几个、为何需组态视角"？案例/数据来源是否明确？
- **红线**：条件数建议 **4–7**（中等样本），过多会加剧有限多样性（limited diversity）。最小样本量属《领域共识》、不同流派差异大，须结合 Ragin 经典文献核实后再写入（见 S3 §2.2 ⚠️）。
- → 参考 S1 §2.2、S3、S4 §3.1。

### Phase 2 — 校准（Calibration）
- **闸门**：是否用 `Calibrate(x, fully in, crossover, fully out)` 三锚点？锚点优先**理论与外部知识**，其次样本描述统计/百分位数；是否透明报告理由与原始值对应表？
- **红线**：
  - 禁止机械套用分位数（33%/67%、均值±标准差）或示例阈值（如 10/0/-9、250/50/10），锚点须有理论/实证依据；
  - 常用方案：Ragin (2008a) `0.95/0.50/0.05`、Fiss (2011) `0.75/0.50/0.25`、偏斜分布 `80%/50%/20%`、七点李克特 `6/4/2`、五点 `4/3/2`——**须据情境调整并透明报告**；
  - 处理 0.5 模糊点常减 0.001（Crilly et al. 2012）；完全隶属案例可 +0.001（Fiss et al. 2011）；
  - 校准后**必须**看"模糊集 vs 原始数据"散点图，确认单调 logistic 形状（见 S5 §2.2）。
- → 参考 S1 §2.5、S3 §2.3、S5 §2.1。

### Phase 3 — 必要性分析（先于充分性）
- **闸门**：是否对结果"高/低"分别做了必要性？是否将条件及其非集（~）都纳入？
- **红线**：**必要性一致性 ≥ 0.9** 才认定必要条件（Fiss 2011 / Misangyi 2014 等）；散点图/子集-超集分析只是探索（非必要步骤），**正式必要性须在软件做**（见 S5 §2.4、§2.7）。
- → 参考 S1 §2.6、S5 §2.7。

### Phase 4 — 真值表（频数 / 一致性 / PRI）
- **闸门**：是否设了 frequency cutoff 与 consistency cutoff？是否结合 **PRI** 处理矛盾组态？是否报告了可观察/不可观察实例比例？
- **红线**：
  - 频数阈值：小样本 = **1**，大样本（如 N>150）应 **>1**（大样本 N>150 时频数阈值 ≥3；并建议保留总案例 ≥75–80%，以公开综述与领域共识为准）；
  - 一致性阈值：充分性常用 **0.80**（Fiss 2011），最低不低于 **0.75**；
  - **PRI ≥ 0.70**（可行取更高；<0.50 表明显著矛盾充分性，须处理）；部分文献用 0.65–0.75；
  - 0.5 边界案例：不被分配真值表行、不进 number 统计，但仍进一致性计算——汇报案例数时要留意（见 S5 §2.5、§3.3）。
- → 参考 S1 §2.6、S3 §2.2、S4 §3.2、S5 §2.6。

### Phase 5 — 充分性分析与解（复杂/中间/简约）
- **闸门**：是否报告了**复杂解 + 中间解**组合？是否区分核心/边缘条件？Assumptions（各条件 present/absent 方向）是否基于理论？
- **红线**：
  - 核心条件 = 同时出现在**中间解与简约解**；仅中间解出现 = 边缘条件（**边缘条件并非不重要**）；
  - 中间解最常用、最易解释；不要用"最简解"过度简化（见 S1 §2.7、S5 §3.1）；
  - 解一致性（solution consistency）应 **>0.75–0.80** 方可接受（真实案例见 S5 §3.2：0.865948）。
- → 参考 S1 §2.7、S5 §3。

### Phase 6 — 结果解释与案例回灌
- **闸门**：是否回到具体案例解释组态？是否对结果"出现"与"不出现"分别建模（**非对称性**）？
- **红线**：禁止只看真值表/逻辑表达式而脱离案例；每个关键组态必须给出案例清单并以质性资料解释机制；不一致/反常案例必须深入分析（见 S1 §3 步骤 8、S5 §4 误区 9）。
- → 参考 S1 §3、S2、S5、S7。

### Phase 7 — 稳健性检验
- **闸门**：是否做了参数敏感性（调一致性/频数/PRI 阈值、调校准锚点）、案例归属（增删关键案例）、校准敏感性？是否报告结果稳定程度与敏感参数？
- **红线**：至少做参数敏感性检验；判定稳健性两维度——**参数拟合**（差异不足以支撑不同实质解释）+ **集合关系状态**（不同检验所得解间具清晰子集关系）（见 S4 §3.2、S6 §4.2 RTP）。
  - **稳健性检验"十二法四原则"**（程恋军、王琳茜, 2025）：十二种方法覆盖参数/案例/校准/模型多层面；四项原则为 **集合优先、多维检验、样本规模适用性、价值说明**；并须重视**动态性分析**与"不稳健"现象——"不稳健"本身可能暴露真实因果机制，应深挖而非简单回避（详见 S1 §3 步骤 6、S6 §4.2 RTP、S4 §3.2）。
- → 参考 S1 §3 步骤 6、S4 §3.2、S6。

### Phase 8 — 理论贡献与写作
- **闸门**：是否明确本文属**理论检验 / 构建 / 扩展**？讨论段是否"回链先验文献"并澄清修正了什么理解？是否区分情境/方法/理论三类贡献？
- **红线**：理论贡献不能过浅（只报路径不回链文献）；构建型须设 holdout 验证样本让理论"挺过第二次评估"（见 S2 §2.5、§3、§4）。
- → 参考 S2、S4 §3.3、S4 §4。

### Phase 9 — 投稿与评审回应
- **闸门**：是否已覆盖审稿人**三大关注点**——①理论框架/组态模型构建；②方法规范/稳健性；③结论解读与升华？
- **红线**：回应须"重述关切→给依据→说明修改→在局限性留痕"；方法论原则："但凡采取更高标准可行时，尽量采取更高标准"（见 S4 §4）。
- → 参考 S4。

## 5. 准确性红线速查（一眼核对）

| 指标 | 经验阈值 | 备注 |
|---|---|---|
| 必要性一致性 | **≥ 0.90** | 低于此一般不认必要条件 |
| 充分性一致性 | **≥ 0.75（底线）/ 0.80（推荐）** | Fiss (2011) 推荐 0.80 |
| PRI 一致性 | **≥ 0.70**（<0.50 严重矛盾） | 部分文献 0.65–0.75 |
| 频数阈值 | 小样本 **1**；大样本 **>1**（N>150→≥3） | 保留 ≥75–80% 案例 |
| 校准锚点 | 理论优先，百分位退用 | 透明报告，禁机械套用 |
| 解类型 | 至少报 **复杂解 + 中间解** | 区分核心/边缘 |
| 非对称性 | 结果"出现/不出现"**分别建模** | 违反即漏机制 |
| 案例回灌 | 每个关键组态**回到案例** | 禁脱离案例的黑箱 |

> 所有阈值为**经验区间而非铁律**，应以目标期刊/文献惯例为准并做稳健性检验。具体领域对 0.8 vs 0.85 的偏好不同（见 S1 §2.6 ⚠️）。

## 6. 完成性核验清单（最终交付前 MUST 全过）

在宣布 QCA 任务完成前，逐项核对：

- [ ] **适配性**：已论证问题具因果复杂性、QCA 优于回归（Phase 0）
- [ ] **设计**：条件选择有依据、数量受控、案例/数据来源明确（Phase 1）
- [ ] **校准**：三锚点有理论/实证依据、透明报告、散点图已检（Phase 2）
- [ ] **必要性**：已做且一致性 ≥0.9；结果高/低均做（Phase 3）
- [ ] **真值表**：频数/一致性/PRI 阈值合理、保留 ≥75–80% 案例（Phase 4）
- [ ] **解**：至少报复杂解+中间解、核心/边缘已区分、解一致性 >0.75–0.80（Phase 5）
- [ ] **解释**：关键组态已回到案例、非对称性已处理（Phase 6）
- [ ] **稳健性**：至少参数敏感性检验、报告稳定程度（Phase 7）
- [ ] **理论/写作**：贡献形态明确、讨论回链文献（Phase 8）
- [ ] **发表就绪**：若投稿，已覆盖三大审稿关注点（Phase 9）
- [ ] **报告完整**：必要/充分一致性、原始与唯一覆盖、解覆盖/一致性、真值表、有限多样性程度、稳健性证据均已呈现

任一未过 → **禁止判定完成**，回到对应阶段纠偏。

## 7. 常见整体失误（贯穿全程）

1. **把相关当集合**：QCA 回答子集/超集关系，对称性误解会反推"低X→低Y"（应分别建模）。
2. **阈值机械套用**：0.8/0.9 等须随样本与文献惯例调整并稳健性检验。
3. **条件过载**：n 条件→2ⁿ 组态，有限多样性与个案化风险陡增。
4. **忽略非对称性**：只分析"高结果"漏掉差异化机制。
5. **滥用直接赋值/锚点照搬**：引入偏见且难解释。
6. **混淆三种解**：中间解≠简约解；核心条件判定依赖两解嵌套对比。
7. **脱离案例**：只报组态不回案例，黑箱化。
8. **稳健性缺失**：只报一种参数设置即声称完成。
9. **理论贡献过浅**：只报路径不回链文献、不区分三类贡献。
10. **混合方法误用**：用 QCA 替代扎根的机制阐释，或用回归净效应替代组态（见 S7）。

- **参考层（本包 8 技能）**：方法论决策、写作规范、结果判读与校对。
- **执行层（本地技能 `qca-analysis-expert`）**：校准、真值表、布尔最小化与代码级执行（本机已就位：`~/.workbuddy/skills/qca-analysis-expert/`）。凡调用本包技能做实证分析，须同步加载该技能执行，并按本包各闸门回传结果校对。
